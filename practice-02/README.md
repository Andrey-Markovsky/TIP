## 4. Модель данных и функции

Каждая задача представляется плоским объектом с четырьмя полями:
- `id` — положительное безопасное целое число (`Number.isSafeInteger(id) && id > 0`), уникальное в пределах списка;
- `title` — строка длиной от 1 до 100 символов после удаления краевых пробелов (`trim()`); внутренние пробелы сохраняются;
- `completed` — логическое значение (`true` или `false`), при создании всегда `false`;
- `priority` — одно из значений `"low"`, `"medium"` (по умолчанию), `"high"`.

**Назначение файлов:**
- `src/data.js` — экспорт неизменяемых стартовых наборов `demoTasks` и `variantTasks`, а также номера варианта `variantNumber`;
- `src/task-service.js` — девять чистых прикладных функций валидации, чтения и иммутабельного обновления списка задач без побочных эффектов и вывода в консоль;
- `src/task-extra.js` — дополнительный модуль с функцией поиска `searchTasks`;
- `src/main.js` — демонстрационный сценарий для общего набора, индивидуального варианта и расширения;
- `checks.js` — автоматизированные проверки на базе `node:assert/strict`.

**Контракты операций:**
- `createTask(id, title, priority)` — при успехе `{ ok: true, task }`, при ошибке `{ ok: false, error }`;
- `findTaskById(tasks, id)` — найденный объект задачи или `undefined` (через `find` и `===`);
- `getPendingTasks(tasks)` — новый массив задач с `completed === false` (через `filter`);
- `getTaskTitles(tasks)` — новый массив строк названий (через `map`);
- `getTaskStats(tasks)` — объект `{ total, completed, pending, progress }` с числовыми полями;
- `addTask`, `setTaskCompleted`, `renameTask`, `removeTask` — при успехе `{ ok: true, tasks }` с новым массивом задач, при ошибке `{ ok: false, error }` без изменения исходных данных.

**Почему id не равен индексу:** индекс отражает только текущую позицию элемента в массиве и сдвигается при удалении предыдущих элементов, а `id` постоянно идентифицирует конкретную задачу независимо от её положения в списке.  
**Почему getTaskStats возвращает число, а не строку с процентом:** функция отвечает за расчёт данных, а не за форматирование вывода; числовое значение `progress` удобно переиспользовать в дальнейших вычислениях и тестах, а `toFixed(1)` применяется только при отображении в `main.js`.  
**Какие объекты копируются при изменении задачи:** создаётся новый массив задач и новый объект именно для изменяемой записи (через spread `{ ...task, ... }`). Остальные неизменённые объекты задач в массиве переиспользуются без мутации.

## 8. Расширение

Выполнен **Вариант А — поиск задач по части названия** в отдельном модуле [`src/task-extra.js`](./src/task-extra.js).

- **Контракт:** `searchTasks(tasks, query)` удаляет краевые пробелы через `trim()`, приводит запрос и названия к нижнему регистру через `toLowerCase()` и возвращает новый массив подходящих задач в исходном порядке (при пустом или пробельнoм запросе — новую поверхностную копию всех задач `[...tasks]`). Исходный массив и его объекты не изменяются.
- **Проверки (сценарий 39 в `checks.js` и вывод в `main.js`):**
  - запрос `" ФУНК "` по `demoTasks` → `[id: 1]` (разный регистр и краевые пробелы);
  - запрос `"методы"` → `[id: 7]`;
  - запрос `"несуществующий фрагмент"` → `[]`;
  - пробельный запрос `"   "` → новый массив из 4 задач (`allCopy !== tasks`);
  - поиск по пустому массиву `[]` → `[]`;
  - неизменность подтверждена через `Object.freeze` на массиве и всех объектах задач.
